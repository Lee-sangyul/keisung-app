# v0.7 개발용 기능 안내: 학년도 전환 · PWA 푸시 · 설문 센터

> **학교 승인 전 실제 학생 개인정보, 출결, 학적을 입력하거나 학생 대상 푸시를 운영하지 마세요.**
> 기존 계정/학생증/교직원증 기능과 동일한 Supabase 프로젝트를 사용합니다.

## DB 설치 순서
기존 `supabase/schema.sql`, `supabase/mvp.sql`이 적용된 프로젝트에서 다음 순서로 SQL Editor에 적용:
1. `supabase/lifecycle.sql` — `profiles.graduated_at`, 진급/졸업 일괄 처리·복원 이력, DB 원자 트랜잭션
2. `supabase/surveys.sql` — 설문/익명 응답/중복 참여 방지 RPC
3. `supabase/push.sql` — 푸시 구독 및 발송 이력

SQL은 기존 프로필을 삭제하지 않습니다. 직접 실행 후 Supabase DB Advisors를 검토하세요.
**실제 DB 적용과 발급/발송은 이 커밋에서 수행하지 않았습니다.**

## 1. 진급·졸업 관리
관리자 전용 `/admin/lifecycle`. 현재 **활성 학생** 전체를 조회하고, 1~5학년은 학년+1, 6학년은 졸업(계정 비활성화) 처리. 반/번호를 유지하기 때문에 새 학년 반 배정이 달라지면 **절대 실행하면 안 됩니다**. 대상자 미리보기와 명단 해시를 서버에서 검사하고 `진급 2027` 같은 최종 확인 문구와 체크박스가 있어야 실행됩니다. 하나의 DB 트랜잭션으로 처리되며 오류 시 전체 롤백. 적용 후 '이전 상태로 복원'은 각 대상 프로필에 후속 변경이 없을 때만 가능합니다. 학년도당 미복원 배치 1개만 허용. 사용 전 DB 백업과 교직원 승인 필수.

## 2. PWA 웹 푸시
구독자는 `/notifications`에서 알림을 스스로 켭니다. 관리자만 수동으로 알림을 전송할 수 있습니다.
대상: 전체/학생/교직원, 학생에게는 학년/반 범위. 운영 테스트 전 구독자 동의 필수.

서버에서 VAPID 키 한 쌍 생성:
```bash
npm install
npx web-push generate-vapid-keys
```
`.env.local`에 다음을 설정합니다 (값은 직접 생성한 키로 교체):
```dotenv
PUSH_ENABLED=true
VAPID_PUBLIC_KEY=<생성한 공개키>
VAPID_PRIVATE_KEY=<생성한 개인키>
VAPID_SUBJECT=mailto:<관리자 연락처>
```
개인키와 `SUPABASE_SERVICE_ROLE_KEY`는 **절대 GitHub에 업로드하지 마세요**. HTTPS, 알림 권한, Web Push 지원 브라우저가 필요합니다. iOS는 설치형 홈 화면 PWA 등 브라우저 제한이 있습니다.
관리자당 최소 2분 간격, 한 번에 최대 1000개 구독 기기까지 발송합니다. 실패/만료 구독을 일부 자동 정리합니다. 발송 완료는 푸시 서비스 수락을 뜻하며 기기 화면 표시를 보증하지 않습니다. **자동 공지 연동·예약 발송은 아직 구현되지 않았습니다.**

## 3. 학생 의견 설문 센터
`/surveys`에서 관리자 설문 작성(단일선택 2~6개 선택지, 학생/교직원/전체, 마감 시각), 사용자는 1회 응답. 설문 응답 투표 테이블에는 사용자 ID가 없고, 참여 중복 방지 테이블과 분리되어 있습니다. 관리자에게는 집계가 바로 보이고, 응답자는 설문 마감 뒤 집계를 볼 수 있습니다. 익명이더라도 접속/응답 시점 등 운영 메타데이터로 신원이 추정되지 않도록 로그 접근과 보존 정책을 정해야 합니다.

## 운영 제한
권한은 API에서도 로그인·프로필 상태로 재검증합니다. PWA 푸시는 지원 환경 및 외부 푸시 서비스에 의존합니다. 실제 운영 전 인증 MFA, CSRF/요청 제한, 개인정보 보존/삭제 정책, 접근 통제와 백업·복원 테스트가 필요합니다.
