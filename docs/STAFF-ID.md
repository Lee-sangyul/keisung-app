# 계성 스마트 개발용 교직원증

학교의 승인 없이 공식 교직원증 또는 출입 인증 수단으로 사용하면 안 됩니다.

## 대상 및 권한
- teacher / admin / superadmin 계정: 개발용 교직원증 발급
- admin / superadmin: QR 서버 검증. 일반 교사는 검증 불가
- student: 교직원증 발급 불가
- 계정 비활성 및 최초 비밀번호 미변경 상태: 발급/검증 거부

## 실행
1. Supabase SQL Editor에서 `supabase/staff-id.sql` 전체 실행 (기존 계정 영향 없음)
2. `.env.local`에 `STAFF_ID_ENABLED=true` 추가. **개발 테스트 전용**
3. `git pull && npm install && npm run dev`
4. 교사/관리자 계정에서 `/staff-id` → QR 발급
5. 관리자 계정에서 `/staff-id/verify` → 카메라 스캔 또는 데이터 입력

## 보안 설계
- 32바이트 무작위 토큰을 QR에 표시하고 DB에는 SHA-256 해시만 저장
- 이름/역할/이메일 등 개인정보는 QR 토큰에 포함하지 않음
- 45초 유효하며 발급 시 이전 미사용 토큰 폐기
- SQL 원자적 UPDATE로 1회 소비 처리 (재사용 불가)
- 검증자가 로그인된 관리자 계정인지 서버에서 다시 확인
- 계정 상태와 역할은 서버에서 조회
- 성공한 검증의 검증자 및 대상 ID를 별도 서버 로그에 기록
- `STAFF_ID_ENABLED`는 기본 비활성. 배포 전 승인 필요

## 여전히 남는 위협
- 만료 전 누군가가 QR을 촬영하고 **먼저** 검증을 시도할 수 있음. QR만으로 화면 소유자를 증명할 수 없음
- 기기 등록/실물 사진 대조/추가 인증, 세션 보안, IP별 요청 제한, MFA, 검증자 감사 기록 보존 정책이 필요
- 이 구현은 개인정보 처리·출입통제 시스템 승인을 받은 공식 교직원증이 아님
- 오래된 QR 로그는 유지보수 작업으로 주기적으로 삭제해야 함
