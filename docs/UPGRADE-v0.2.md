# Keisung Smart v0.2 관리자 기능 업데이트

1. Codespaces에서 `git pull` 실행
2. Supabase 대시보드 → SQL Editor → `supabase/account-management.sql` **전체 내용 실행**
3. `npm run dev` 재시작
4. 관리자로 로그인 → `/admin` → **테스트 전용 계정** 발급
5. 계정 비활성화·재활성화 및 비밀번호 초기화와 감사 기록 확인

안전장치:
- 누구도 자신의 계정을 관리자 화면에서 비활성화하거나 초기화할 수 없음.
- 시스템 관리자는 다른 시스템 관리자를 관리할 수 없음.
- 일반 관리자는 학생·교사 계정만 관리 가능.
- 새 임시 비밀번호는 한 번만 반환되며 로그 테이블에 저장하지 않음.
- 모든 관리자 API는 서버에서 JWT와 프로필 권한·disabled 값을 다시 확인.
- 비활성화 시 Supabase Auth 계정에도 ban을 적용함.
- 이미 발급된 Access Token은 유효기간까지 남을 수 있으므로 API가 매번 disabled를 검사함.

**주의:** 감사 기록 삽입이 실패한 작업은 오류로 표시되지만 일부 Supabase Auth 상태 변경은 먼저 적용됐을 수 있음. 실패 시 반복 클릭하지 말고 대상 계정 상태를 확인하세요. 동시 관리자 수정과 로그인 시도 제한, rate limiting, 운영 로그/백업은 추가 과제입니다. 학교 승인 전 실제 학생 계정 사용 금지.
