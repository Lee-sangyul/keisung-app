# 개발용 모바일 학생증 · QR 검증

학교의 공식 승인 없이 본 기능을 공식 학생증으로 사용하면 안 됩니다.

## 시작하기
1. Supabase SQL Editor에서 `supabase/student-id.sql` 전체 실행
2. `.env.local`에 `STUDENT_ID_ENABLED=true` 추가 (개발 테스트에만 사용)
3. `npm install` → `npm run dev`
4. 테스트 학생 계정 발급 후 학년/반/번호 입력, 최초 비밀번호 변경
5. 학생 계정은 `/student-id`에서 QR 발급
6. 테스트 교사 계정은 `/student-id/verify`에서 카메라 스캔 또는 QR 문자 붙여넣기로 서버 검증

## 위조·재사용 방지
- 학생 로그인 확인 후 32바이트의 암호학적 난수로 일회용 불투명 토큰 발급
- DB에는 SHA-256 해시만 저장하며 QR 문자열에 이름/학년/번호를 넣지 않음
- 45초 유효, 발급 시 이전 QR 폐기
- 서버 측 단일 원자적 UPDATE로 한 번만 소비; 재사용은 HTTP 410
- 검증은 교사·관리자 계정만 사용 가능; 검증된 학적 사항을 서버에서 조회
- 학생 계정 비활성화/첫 로그인 미완료 시 발급 거부

## 한계와 필수 운영 조치
- 실시간 QR의 스크린샷도 **만료 전 최초 1회**에는 재생할 수 있습니다. 단순 QR만으로 화면 원본임을 증명할 수는 없습니다.
- 실제 학교 운영 전 교직원 인증 강화, HTTP rate limiting, 카메라 검증 디바이스 등록, 추가 본인확인, 고유 사진 비교 등 검증 정책이 필요합니다.
- QR에는 학적 데이터가 없으나 서버에서 조회하는 개인정보에는 학교 승인·동의/보존정책이 필요합니다.
- 누적 DB 행 정리 잡을 추가해야 하며, 카메라 스캔은 HTTPS와 브라우저 BarcodeDetector 지원이 필요합니다.
- **기본값은 비활성화**. 학교 승인 및 보안 검토 전 개발 테스트 환경에서만 활성화하세요.
