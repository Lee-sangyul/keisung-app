# [Keisung App] v0.8 — 분실물 센터 & 나만의 시간표

## 배포 전 설정
1. 기존 Supabase 프로젝트에서 `supabase/schema.sql`이 적용됐는지 확인
2. SQL Editor에서 `supabase/school-life.sql` 전체 실행
3. Codespaces에서 `git pull && npm install && npm run dev`
4. **테스트 계정으로만** 등록/조회 기능 검증. 실제 학생 정보는 학교 승인·권한·보존정책 수립 전 사용 금지

기존 계정과 학생증 정보는 변경되지 않으며, 기자재 관리 기능은 추가하지 않았습니다.

## 분실물 센터
- 주소: `/lost-found`
- **admin / superadmin**: 분실물 등록(이름, 습득 장소, 습득일, 특징, 선택 사진), '수령 완료' / '다시 공개' 상태 변경 및 전체 목록 조회
- **student / teacher**: '보관 중' 목록과 사진 조회·검색만 가능. 생성·수정·삭제 API는 관리자만 접근
- 사진은 JPG/PNG/WEBP 3MB 이하. 비공개 Supabase Storage 버킷 `keisung-lost-found`에 저장하며, 로그인 인증을 통과해야 15분짜리 읽기 링크가 생성됩니다.
- 수령 완료 항목은 학생 목록에서 사라지고 관리자 기록에는 남습니다.
- 실제 학생 이름·연락처·식별 가능한 사진 등을 설명/사진에 넣지 마세요. 사진은 재배포될 수 있습니다.
- 분실물 수령인 확인이나 물품 폐기는 관리자 현장 절차로 운영하세요.

## 에타 스타일 학생 개인 시간표
- 주소: `/timetable`
- 학생 본인이 월~금 1~8교시 그리드의 빈 칸을 터치해 과목, 장소, 담당 교사, 색상, 연속 교시를 등록
- 색 블록 선택 후 수정/삭제 가능. PC에서도 조작할 수 있고 좁은 모바일은 가로 스크롤 지원
- 서버에서 학생의 로그인 ID와 소유권을 검증하고, SQL 원자적 함수에서 교시 중복을 차단
- 교직원과 다른 학생은 특정 학생의 개인 시간표를 조회·수정할 수 없음
- **학교 공식 시간표와 연동되지 않는 개인 작성표**. 시간표가 학교의 공식 자료인 것처럼 공유하지 마세요.

## 테스트 시나리오
1. 관리자: 사진 없이 분실물 추가 → 관리자에게 표시 → 수령 완료 → 학생 목록에서 숨겨짐
2. 학생: 분실물 목록 조회 가능, POST /api/lost-found 시 HTTP 403
3. 학생 A: /timetable 1~2교시 과목 등록 → 겹치는 교시 추가 시 거절
4. 학생 B: 학생 A의 시간표가 보이지 않는지 확인
5. 교사/관리자: /api/timetable 쓰기 요청 시 HTTP 403
6. 화면 크기: 360px 스마트폰 / 태블릿 / 16:9 데스크톱에서 UI 조작 확인

실제 배포 시 보관 기간, 관리자 수정 이력, 대용량 사진 처리, 데이터 백업, 권한·레이트리밋 점검을 추가해야 합니다.
